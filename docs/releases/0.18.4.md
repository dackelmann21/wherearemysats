# Release 0.18.4 – Patch: REG-1, Acquisition-ID, Source beim CSV-Import

Stand: 2026-10-13. Patch-Release im Feature-Freeze mit zwei vom Owner autorisierten
Freeze-Ausnahmen (FIX-UI-4, REG-1). Details:
Anforderung REG-1 und Beta-Block (intern dokumentiert).

## Für den Betreiber

- **Schema 23 → 24**: neue Spalte `known_addresses.key_access` (Default 1). **Vor dem
  Update ein Backup nach `INSTALL.md`, Abschnitt 10, anlegen.** Die Migration läuft
  beim Start automatisch und nur vorwärts; zurück geht es nur über das Backup. Bestehende
  Einträge behalten den Schlüsselzugriff und verhalten sich unverändert.
- Bei einer Neuinstallation ist nichts zu migrieren (eine leere DB wird beim ersten Start
  mit Schema 24 angelegt).
- Die Assets werden mit `?v=0.18.4` ausgeliefert.

## Neu

- **REG-1: Registry-Adressen „ohne Schlüsselzugriff“**: Eigentum ja, Verwahrung nein.
  Eine solche Adresse bleibt Eigentumsnachweis (Outputs OWNED, Herkunft über sie gültig),
  wird aber nicht im Wallet Inventory gescannt und nicht zum Bestand gezählt. Ein dokumentierter, unverbrauchter Acquisition-Output auf
  ihr erscheint als „Documented — not in current wallets“. Auswahl „Key available“ / „No key
  access“ bei „Owned“ (Output-Dialog, Classify-Ansicht), Umschalten in Known Addresses.
  API: `PATCH /api/registry/addresses/{address}` mit `{"key_access": bool}`.
- **Acquisition-ID**: Records & Origins zeigt die Datenbank-ID als `#n` über dem
  Datum; Find sucht mit `#n` oder `n`.
- **„Source for all rows“ im CSV-Import**: Dialogfeld als Vorgabe für leere
  `source`-Zellen; eine nicht leere Zelle gewinnt. Bestehende Acquisitions werden nicht
  verändert.

## Geändert

- **Find trifft die ID nur noch exakt**: `4` findet #42 nicht mehr. Textfelder werden
  weiter als Teilstring durchsucht.

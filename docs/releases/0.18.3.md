# Release 0.18.3 – Patch: FIX-EXIT-1, FIX-EXIT-2 und zwei Restfixes

Stand: 2026-10-13. Patch-Release im Feature-Freeze, nur Fehlerbehebungen. Details:
Anforderungen FX-1 und FX-2 (intern dokumentiert).

## Für den Betreiber

- **Keine Schema-Änderung**: Das Schema bleibt 23, kein Migrationsschritt.
- 0.18.3 enthält 0.18.2 vollständig ([`0.18.2.md`](0.18.2.md)).
- Die Assets werden mit `?v=0.18.3` ausgeliefert.
- **Hinweis in der Exit-Ansicht:** Nach dem Update kann die Exit-Ansicht bei bestehenden
  Exits melden, dass die gespeicherte Zuordnung von der On-Chain-Auswertung abweicht.
  Das betrifft früher gespeicherte Exits, bei denen ein MIXED-Input mit Betrag unter der
  Acquisition gespeichert wurde, aus der der Editor geöffnet war (erfundene Zuordnung).
  Es wird nichts automatisch geändert.

## Geändert

- **FX-1: Exit-Editor zeigt alle Inputs**: Der Editor listet
  jeden Input der Exit-TX mit Klasse und Ankern aus derselben Auswertung wie
  `exit_provenance_rows`, unabhängig davon, aus welcher Acquisition er geöffnet wird. Ein
  Input ist nur dann Quelle einer Acquisition, wenn die Auswertung genau diese eine
  Acquisition nennt. Behebt den offenen Punkt aus 0.18.2.
- **FX-2: MIXED-Inputs ohne Aufteilung**: Eine Exit mit
  MIXED- oder Mehrfach-Acquisition-Input lässt sich speichern. Solche Inputs werden je
  Anker-Acquisition ohne Betrag gespeichert (0/0) und verringern keinen Restbetrag. Die
  Acquisition zeigt „Involved (not attributed)“ ohne Betrag. Eine gespeicherte Exit wird
  nicht mehr als Kandidat angeboten.
- **Abweichungshinweis**: `GET /api/exchange-exits/{id}` liefert
  `allocation_check` (MATCHES/DIFFERS/UNAVAILABLE); die Exit-Ansicht zeigt bei DIFFERS
  einen Hinweis mit der Abweichung. Nur lesend.
- **Exits-CSV**: 0/0-Zeilen werden nicht als `RECORDED_SOURCE` ausgewiesen.
- **Workspace-Snapshot**: liefert `unattributed_inputs` je Exit, damit die
  Acquisitions-Seite „Involved (not attributed)“ zeigt.

## Behobene Fehler

- **REMAINING negativ**: Die Acquisitions-Seite zeigte für jede Acquisition mit
  Exit „0 − zugeordnet“, also einen negativen Wert. Der Workspace-Snapshot las die
  Acquisitions direkt aus der Tabelle; `btc_amount` gibt es dort nicht als Spalte, es wird nur beim
  Lesen über die API aus `origin_amount_sats` abgeleitet. Der Snapshot nutzt jetzt
  dieselbe Ableitung. REMAINING = Betrag − zugeordnete Summe; 0/0-Zeilen zählen nicht.
- **Serverseitige Prüfung FX-2**: Bisher verhinderte nur der Editor, dass ein
  Input ohne eindeutige Acquisition (MIXED, mehrere Acquisitions, ungeklärter Ursprung)
  mit Betrag unter einer einzelnen Acquisition gespeichert wird. Das Anlegen lehnt das
  jetzt mit 409 und einer Meldung mit dem Outpoint ab; dieselbe Auswertung wie Editor und
  `exit_provenance_rows`. Ohne Betrag (0/0) bleibt das Speichern möglich. Bestehende
  Exits werden nicht geprüft und nicht geändert.
